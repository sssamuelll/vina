# Pleats & Folds Tool Design

> Issue #260 — Accordion Pleats & Create Fold Tool (Sub-project A: data model, UI, copilot)
> 3D simulation deferred to #429

## Overview

Pleat creation tools (knife, box, accordion, inverted box) and fold/crease lines with mountain/valley direction. A `Pleat` entity captures the construction parameters (type, depth, spacing, count, edge). It generates stored `InternalLine` entries with `foldOptions` metadata. The fold lines render in 2D with direction markers and export via existing DXF/PDF pipelines.

## Data Model

### Pleat Entity

New interface in `src/types/types.ts`, stored as `ProjectState.pleats: Pleat[]`.

```typescript
export type PleatType = 'knife' | 'box' | 'accordion' | 'invertedBox';

export interface Pleat {
  id: string;
  pieceId: string;
  edgeName: string;           // semantic edge where pleats run
  type: PleatType;
  depth: number;              // fold depth in mm (perpendicular to edge)
  spacing: number;            // distance between pleat centers in mm
  count: number;              // number of pleat repeats (1–50)
  direction: 'left' | 'right'; // knife pleat fold direction (ignored for symmetric types)
  tStart: number;             // 0–1 parametric start on edge (default 0)
  tEnd: number;               // 0–1 parametric end on edge (default 1)
  generatedLineIds: string[]; // IDs of InternalLine entries this pleat owns
}
```

### FoldOptions on InternalLine

Added to the existing `InternalLine` interface, following the `notchOptions`/`topstitchOptions` pattern:

```typescript
foldOptions?: {
  direction: 'mountain' | 'valley';
  creaseAngleDeg: number;     // 180 = flat fold (default), 90 = right angle
  pleatId?: string;           // back-reference to owning pleat (undefined for manual folds)
}
```

Any `InternalLine` with `type: 'fold'` can carry `foldOptions`. Fold lines created manually via the fold tool have `pleatId: undefined`. Fold lines generated by a pleat have `pleatId` set.

### Defaults

| Property | Default | Rationale |
|----------|---------|-----------|
| type | `'accordion'` | Most common pleat type |
| depth | 15 | 15mm is standard pleat depth |
| spacing | 20 | 20mm between pleat centers |
| count | 4 | Reasonable starting count |
| direction | `'left'` | Knife pleat convention |
| tStart | 0 | Full edge |
| tEnd | 1 | Full edge |
| creaseAngleDeg | 180 | Flat fold |

## Fold Line Generation

### Module: `src/utils/pleatGeometry.ts`

Pure function `generatePleatFoldLines(pleat, piece): InternalLine[]`.

Takes a `Pleat` entity and the `PatternPiece` it belongs to. Samples the named edge within `tStart`–`tEnd`, computes fold line positions along the edge, and returns `InternalLine[]` with `type: 'fold'` and `foldOptions`.

### Algorithm

1. Find the `SemanticEdge` by `edgeName` on the piece.
2. Sample `count * linesPerPleat` evenly-spaced positions along the edge within `tStart`–`tEnd`. The number of lines per pleat depends on the type.
3. At each position, compute the edge tangent and the perpendicular direction.
4. Create a fold line path: a straight line perpendicular to the edge, with length = `depth`, starting at the edge point and extending inward.
5. Assign `foldOptions.direction` (mountain/valley) based on the pleat type and position.

### Lines Per Pleat Type

**Knife** — 1 line per pleat repeat:
- All mountain, spaced `spacing` apart.
- `direction` field on pleat controls which side the fold faces (visual only for 2D; physics in #429).

**Box** — 2 lines per pleat repeat:
- Both mountain, separated by `depth`, centered on the pleat position.
- Creates a box shape on the fabric surface.

**Accordion** — 2 lines per pleat repeat:
- Alternating mountain/valley, separated by `spacing / 2`.
- Creates zigzag folding.

**Inverted Box** — 2 lines per pleat repeat:
- Both valley, separated by `depth`, centered on the pleat position.
- Inverse of box pleat.

### Edge Cases

- `count = 0`: returns empty array.
- `count > 50`: clamped to 50 to prevent reducer blocking.
- Edge not found: returns empty array.
- `spacing` too large for edge length: generates as many pleats as fit, silently reduces count.
- `depth` clamped to piece bounding box height to prevent fold lines extending beyond the piece.

## Redux State

### ProjectState Extension

```typescript
pleats: Pleat[];
```

Added to `ProjectState` interface and `initialState` (as `[]`).

### Reducers

**`addPleat(state, action: PayloadAction<Omit<Pleat, 'generatedLineIds'>>)`:**
1. Validate piece exists and edge exists on piece.
2. Call `generatePleatFoldLines` to compute fold lines.
3. Add fold lines to `piece.internals`.
4. Store `generatedLineIds` on the pleat.
5. Push pleat to `state.pleats`.

**`updatePleat(state, action: PayloadAction<Partial<Pleat> & { id: string }>)`:**
1. Find existing pleat.
2. Rebuild ownership: scan `piece.internals` for lines with `foldOptions.pleatId === pleatId` to find current owned lines (not `generatedLineIds`, which may be stale if the user manually deleted a fold line).
3. Remove owned fold lines from `piece.internals`.
4. Merge updates into pleat.
5. Recompute fold lines via `generatePleatFoldLines`.
6. Add new fold lines to `piece.internals`.
7. Update `generatedLineIds` from the newly generated line IDs.

**`removePleat(state, action: PayloadAction<string>)`:**
1. Find pleat by ID.
2. Remove its generated fold lines from `piece.internals`.
3. Remove pleat from `state.pleats`.

### Cascades

**`removePiece`:** Extended to filter `state.pleats` by `pieceId` (fold lines already removed since they're in `piece.internals`).

### Fold Line Ownership

`generatedLineIds` on the `Pleat` entity is a convenience cache, not the source of truth. The authoritative ownership signal is `foldOptions.pleatId` on each `InternalLine`.

**If the user manually deletes a pleat-generated fold line** (via `removeInternalLine`), the pleat's `generatedLineIds` becomes stale — it references a deleted ID. This is harmless: `updatePleat` rebuilds ownership by scanning `piece.internals` for `foldOptions.pleatId === pleatId`, so it finds the correct current set regardless of manual deletions.

**If the user manually adds a fold line** with the same `pleatId` (unlikely but possible via copilot), it will be claimed by the pleat on next update and replaced. This is acceptable — manual fold lines should use `pleatId: undefined`.

Covered by `projectSlice` resetting to `initialState` which includes `pleats: []`.

## UI Interaction

### Hook: `usePleatTool`

Located at `src/hooks/usePleatTool.ts`. Edge-based interaction following the elastic tool pattern.

**Flow:**
1. User activates pleat tool from toolbar.
2. Hover highlights edges (reuse edge hit-testing from elastic/seam tools).
3. Click edge → dispatch `addPleat` with defaults.
4. If edge already has a pleat, clicking selects it for editing.
5. Properties panel shows pleat config (type, depth, spacing, count, direction, tStart/tEnd).
6. Parameter changes dispatch `updatePleat` which recomputes fold lines.

**Returns:** `hoveredEdge`, `selectedPleatId`, `handleMouseMove`, `handleMouseDown`.

### Fold Line Tool Enhancement

The existing `addFoldLine` copilot tool is upgraded to accept `direction` and `creaseAngleDeg` parameters. The internal line drawing interaction (manual fold lines) remains unchanged — the user draws a line, and the properties panel shows direction/angle options.

## 2D Rendering

### Existing Fold Line Rendering

Fold lines already render as purple dashed lines in `PieceRenderer.tsx` (line ~200). Enhancements:

**Mountain fold markers:** Small upward triangles (▲) placed every ~20 screen pixels along the fold line (zoom-aware spacing). Color: purple (#9c27b0).

**Valley fold markers:** Small downward triangles (▼) placed every ~20 screen pixels along the fold line (zoom-aware spacing). Color: blue (#3F51B5).

**Pleat grouping indicator:** When multiple fold lines belong to the same pleat, a thin connecting bracket runs along the edge between the first and last fold line. Color: gray, 0.4 opacity.

Implementation: Extend the fold-line rendering branch in `PieceRenderer.tsx` to check `foldOptions` and add marker elements.

## Copilot Tools

### File: `src/copilot/action/tools/definitions/pleatTools.ts`

**`createPleat`:**
- Parameters: `pieceId` (required), `edgeName` (required), `type` (required), `depth`, `spacing`, `count`, `direction`, `tStart`, `tEnd`
- Validates piece and edge exist
- Dispatches `addPleat` with defaults for omitted params
- Returns created pleat data + generated line count

**`removePleat`:**
- Parameters: `pleatId` (required)
- Validates pleat exists
- Dispatches `removePleat`

**`updatePleat`:**
- Parameters: `pleatId` (required) + optional fields
- Validates pleat exists
- Dispatches `updatePleat`

### Upgraded `addFoldLine` in `internalTools.ts`

Add optional parameters to existing tool:
- `direction`: `'mountain' | 'valley'` (default `'mountain'`)
- `creaseAngleDeg`: number (default 180)

These populate `foldOptions` on the created `InternalLine`.

### Registration

All pleat tools registered in `src/copilot/action/tools/registry.ts` via the standard `ALL_TOOL_MODULES` pattern.
