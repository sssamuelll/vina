## 0. The ask

> **Samuel, 2026-09-29:** *«vamos a trabajar en un working tree aparte para meterle i18n a todo
> vina modo seriedad (con inglés, español y alemán por ahora)»* — "let's work in a separate
> worktree to put i18n into all of Vina, serious mode (English, Spanish and German for now)".
>
> And, on seeing that Spanish was going to be the source: *«yo preferiría que todo el desarrollo
> se internacionalice (que todo pase a inglés como por defecto)»* — "I'd rather the whole
> development be internationalized (everything moves to English as the default)".

"Serious mode" is read as five commitments, confirmed in the conversation:

1. **Total coverage.** No surface mixes languages, in any of the three.
2. **A ratchet.** A new hard-coded string fails the pre-commit, like the rest of the UI contract.
3. **Trade vocabulary comes from a glossary**, not from literal translation (pinza → dart /
   Abnäher, piquete → notch / Knipser, margen de costura → seam allowance / Nahtzugabe).
4. **María notices nothing** except changes decided on purpose (the decimal comma, § 5.7).
5. **The repository itself moves to English**: code, comments, tests, commits, specs, living docs.

"For now" means a fourth language must be cheap: one catalog folder, one glossary column, one
lock column.

## 3. Scope

**In: everything a person reads, or hears through a screen reader.**

- The app: chrome, panels, menus, command palette, dialogs, toasts, tooltips, `aria-label`s,
  empty states, errors, error boundaries.
- Product catalogs: fabrics, trims, blueprints, 2D tools and their options, measurement names,
  shortcut labels.
- The copilot towards the person: errors painted in the AI bar, its settings, suggestions, and the
  language it answers in.
- Documents for people: the BOM, whatever the 1:1 PDF prints, export toasts.
- The home: three static pages with their titles, descriptions and OG images.
- Numbers and key names.
- The repository's own language (§ 9.3).

**Out:**

- **Model-facing text:** tool descriptions (~258 tools), system prompts and tool results meant
  for the model stay English. The model is told which language to answer in (§ 6.3).
- **Machine-read tokens:** DXF AAMA blocks and attributes (its only Spanish strings are comments),
  storage keys, IDs, `choices` values (`'flat-felled'`, `'outward'`), tool IDs in the AI trace (D6).
- **The person's data:** names she typed, and names generated when an object was created, are
  never re-translated when the language changes.
- Units (D11). CLI and server messages (five developer-facing files). Right-to-left scripts. Swiss
  German and British English.
- `languagePacks.ts` and `languageDetection.ts`: deleted, not translated (§ 6.3).

## 4. Principles

1. **Translate at read, never at write.** What is stored is an ID; the text is asked of the catalog
   when painting or exporting. Precedents: #1194's `mensajeDeErrorEs`, and the trim dropdown that
   showed `nameEs` but stored `name`, so the BOM printed «Botón — Flat Button 15mm».
2. **Whole sentences.** Never concatenate translated fragments: German reorders words, and Spanish
   and German agree in gender. Parameters go inside one message.
3. **English is the source; the glossary governs all three languages.** Spanish that María signed
   moves verbatim into `es`, except number formatting (§ 5.7). It is not re-derived from English.
4. **Variants:** `en` (US spelling), `es` (as today), `de` (Germany, with ß).
5. **Nothing visible in module-level constants.** Menus, shortcuts, tool definitions and presets
   are evaluated at import time; text stored there would freeze in the boot language. They hold a
   selector or an ID instead.
6. **What a machine reads is never translated.**

## 5. Core (`src/i18n/`)

### 5.1 Layout

```
src/i18n/
  en/          source: one file per area (shell.ts, editor2d.ts, viewport3d.ts, properties.ts,
               copilot.ts, exports.ts, errors.ts, keys.ts, catalogs.ts, …) and index.ts
  es/  de/     the same files; each area object `satisfies Catalog['<area>']`
  types.ts     Catalog = Widen<typeof en>
  index.ts     getLocale · setLocale · subscribe · detectLocale · t() · useT()
  format.ts    helpers(locale) → { num, plural } · formatNumber · parseNumber
  pseudo.ts    development-only pseudo-locale derived from `en`
  lock.json    the translation lock (§ 7.3)
```

### 5.2 Catalog shape

```ts
// src/i18n/en/pieces.ts: the source
const { num, plural } = helpers('en');
export const pieces = {
  delete: 'Delete piece',
  selected: (n: number) => plural(n, { one: '1 piece selected', other: `${n} pieces selected` }),
  lengthDiff: (mm: number) => `${num(mm, 1)} mm difference`,
};

// src/i18n/de/pieces.ts (German wording illustrative until the glossary review)
const { num, plural } = helpers('de');
export const pieces = {
  delete: 'Schnittteil löschen',
  selected: (n: number) => plural(n, { one: '1 Schnittteil ausgewählt', other: `${n} Schnittteile ausgewählt` }),
  lengthDiff: (mm: number) => `${num(mm, 1)} mm Differenz`,
} satisfies Catalog['pieces'];   // a missing or extra key fails `tsc -b` in the pre-commit
```

- `Catalog` is `Widen<typeof en>`: string literals widen to `string`, functions keep their
  signature, objects recurse.
- Each catalog formats with **its own** locale's helpers, so German prints "12,3" even when the
  review document is generated while the app runs in English.
- `plural` uses `Intl.PluralRules` of the catalog's locale.
- Data by ID (fabrics, trims, blueprints, measurements, tools, shortcuts) are `Record<Id, …>` over
  the ID union exported by the data module, so an unknown ID in code is a type error. Data read
  from old projects goes through the fallback of § 6.2.

### 5.3 Access

- In React: `const t = useT()`, built on `useSyncExternalStore(subscribe, getLocale)`. A language
  change re-renders without a reload.
- Outside React (middleware, exporters, copilot): `t()` returns the active catalog at call time.
- `t()` at module scope is forbidden (it would freeze); the lint rule of § 8.1 flags it.

### 5.4 State, persistence, detection

- The active locale is module state with a subscription, **not Redux**: it is not part of the
  document, Ctrl+Z must not undo it, and code outside React reads it synchronously.
- It is persisted in the `localStorage` key `vina-locale` through `safeGetItem` / `safeSetItem`
  (`src/utils/safeStorage.ts`), with the inline justification CLAUDE.md requires for LS-only
  writes: it must be read synchronously before the first render (IndexedDB is async and would
  flash the wrong language), and the home and the app share it (same origin, homepage spec D4).
- `detectLocale()`: the stored choice; otherwise the first `navigator.languages` entry whose
  primary subtag is supported (`es-VE` → `es`, `de-AT` → `de`, `en-GB` → `en`); otherwise `en`.
- `<html lang>` is set at boot from `detectLocale()` and on every change (screen readers, and
  `hyphens: auto`, which German compounds need). The static `lang="en"` of `app/index.html`
  becomes the correct default.

### 5.5 The door

- A **Language** submenu in the Vina menu (`src/components/shell/LogoMenu.tsx`), next to Units,
  with each language named in itself: English · Español · Deutsch. (UI contract Law 6: a
  dispatched function has a visible door.)
- On the home: a switcher in the header (§ 6.5).

### 5.6 Keys

- `shortcutDisplay.ts` takes modifier and key names from the `keys` area of the catalog (German
  `Strg`, `Umschalt`, `Entf`, `Leertaste`; the glossary fixes the exact words). Spanish keeps
  today's `Ctrl`, `Shift`, `Supr`.
- Bindings do not change: `e.key` and the CLO3D mapping are the same in every language, and so
  are the macOS glyphs.

### 5.7 Numbers

- `formatNumber(value, { decimals })` wraps `Intl.NumberFormat(locale, { useGrouping: false,
  maximumFractionDigits })`. Spanish gains the decimal comma the cotas already use: this is the
  only change María sees.
- `parseNumber(text): number | null` is the single parser for every numeric text input. It
  accepts `,` or `.` as the decimal separator (never as grouping), an ASCII or Unicode minus,
  surrounding spaces and the unit suffix the field itself paints. Anything else returns `null`:
  never `NaN`, never `0`. `parseMedida` becomes a caller of it, and the ~90 numeric input sites
  move to it.
- The `toFixed` calls whose result reaches a person move to `formatNumber`. Those that build
  machine output (DXF, CSV numeric cells, CSS, storage) stay.

### 5.8 Bundle

All three catalogs ship in the app bundle (estimated 25–35 KB gzip each; measured in phase 0). A
`// ponytail:` comment marks the ceiling: split per locale with a dynamic import when a fifth
language arrives or the bundle budget asks for it.

### 5.9 Pseudo-locale

`pseudo` exists only in development and e2e (`?locale=pseudo`) and never appears in the menu. It
is derived from `en` at runtime: accented letters, ~35 % expansion, brackets
(«[Ðéļéţé þîéçé ···]»). It makes any string that bypassed the catalog visible at a glance, and it
stresses layouts the way German does (§ 8.3).

## 6. Surfaces

### 6.1 App UI (~2,000 strings)

- Migrated by area, from a newcomer's path inward: empty state and import → shell (Vina menu,
  dock, tool strip, AI bar, toasts) → 2D editor (`PatternEditor`, `src/tools/definitions`, cotas) →
  properties (`PropertiesPanel`, `LayerPanel`) → 3D (`Viewport3D`) → bottom panel (`BottomPanel`,
  diagnostics) → error boundaries and the rest.
- For each area:
  1. A codemod built on the census AST proposes every candidate with its `file:line` and a
     suggested key.
  2. An agent decides the key, the parameters and the whole-sentence shape.
  3. The English source is written through the solace-wren microcopy protocol.
  4. The Spanish goes verbatim to `es/`; the German is written with the glossary.
  5. The area's tests move to catalog references (§ 8.2), and its files leave the debt list
     (§ 8.1).
- Module-level definitions (`LogoMenu` items, `DEFAULT_SHORTCUTS` labels, tool definitions) move
  from `label: 'Proyecto nuevo'` to a selector, `label: (t) => t.menu.file.newProject`, or to an ID
  looked up at paint time.

### 6.2 Product catalogs and stored names

- The 72 `…Es` fields go. Fabrics, trims, blueprints and measurements keep their ID; the visible
  name comes from the catalog (`t().catalogs.fabrics[id]` and so on).
- Where a project stores a display name today (a trim's name, which
  `src/utils/trim/trimExtractor.ts` copies into the BOM), it also stores `presetId`: a new optional,
  backward-compatible field, with its shape comment and zod envelope as B6 requires. Reading:
  `presetId` known → the catalog name in the active language; otherwise → the stored name (old
  projects, items she named).
- Default names for new objects come from the catalog in the active language at creation time.
  From then on they are her data.
- Copilot tools that pass `nameEs` (`fabricTools.ts`, `trimTools.ts`, `blueprintTools.ts`) expose
  the ID and the active-language name instead. The `nameEs` parameter of `blueprintTools` becomes a
  plain `name`, in the conversation's language.
- 2D tool names, tool options (the territory of `idiomaDeOpciones.test.ts`) and shortcut labels
  resolve by ID.

### 6.3 Copilot

- The system prompt states the interface language and asks the model to answer in the language
  the person writes in, falling back to the interface language when unclear. The three hard-coded
  Spanish directives in `domainBootstrap.ts` go.
- `mensajeDeErrorEs` becomes `errorMessage` and reads from the catalog. It stays translate-at-paint:
  `classifyError` and the model's retry keep reading the raw error.
- `languageDetection.ts` and `languagePacks.ts` are deleted.
- What the copilot creates (piece names, colorway names) is born in the conversation's language
  and is data from then on.
- `teachingContext.ts`: nobody paints its snippets. The switch label is translated; wiring the
  feature or deleting it is a separate decision (§ 12).
- The copilot's person-facing UI (`UnifiedBar*`, `AgentSettings`, connections, provider settings,
  the suggestions in `InspectorTab`) migrates with the shell area.

### 6.4 Exports

- The BOM (`src/utils/export/bomExtractor.ts`), whatever the 1:1 PDF prints
  (`src/utils/exportPDF.ts`) and the export toasts (`src/utils/export/uiExport.ts:20`,
  «Exporté tu patrón en PDF.») render in the language active at export time.
- The BOM CSV translates its headers and text cells; its numeric cells stay machine-neutral
  (period decimal, comma delimiter), because a spreadsheet parser reads the file before a person
  does.
- The diagnostic bundle (`src/utils/export/diagnosticExporter.ts`) is read by whoever gives
  support: English, untranslated.
- The DXF AAMA export (`src/utils/dxf/exportAAMA.ts`) does not change.

### 6.5 Home

- One template and a home catalog (English source, Spanish, German) generate three static pages:
  `/` in English (also `x-default`), `/es/` and `/de/`. Each page carries its `<html lang>`,
  `hreflang` links to all three plus `x-default`, and its own `<title>`, description and OG image
  (today's OG text: «Traza el patrón, mira la caída.»).
- A script generates the pages and they are committed. A test fails when the committed pages drift
  from template plus catalog, the same idea as the committed WASM binaries.
- The `incluirEnHome` plugin in `vite.config.ts` already applies to every `index.html` except
  `app/index.html`, so `es/index.html` and `de/index.html` get their includes; the build gains two
  inputs.
- No automatic redirect. When `navigator.languages` prefers another available language and no
  choice is stored, a discreet strip offers it.
- Choosing a language on the home writes `vina-locale`, so `/app/` opens in it.
- nginx needs no change: `location /` with `try_files $uri $uri/ =404` (homepage-nginx spec)
  serves `/es/` and `/de/` from their `index.html`.
- **Amends the homepage spec 2026-09-28**, whose § 1 listed `/en/` as a non-goal and whose § 10
  kept it as a follow-up: with D5 the root is English and Spanish moves to `/es/`.
  `scripts/deploy-prod.sh:248` checks `/` for «Traza el patrón»; it must check the English tagline
  at `/` and the Spanish one at `/es/`. `tests/e2e/home.spec.ts` runs for the three pages.

## 7. Translation quality

### 7.1 Glossary first

1. **A trilingual glossary**, `docs/specs/2026-09-29-ui-glossary.md` (English source · Spanish ·
   German · note), built from the 2026-07-16 glossary plus the terms found during extraction
   (about 80 expected). The old file stays as a record, with a pointer to the new one.
2. The German column is researched in sector references, CLO3D's German UI included, since many
   users come from it. **The native reviewer approves the glossary before bulk translation**:
   correcting 80 terms is cheap, correcting 2,000 strings is not.
3. Bulk translation, area by area, with the glossary.
4. Review: the native reviewer for German, Samuel for English (§ 7.5).

### 7.2 Style per language (replaces UI contract Law 5)

- **en:** sentence case; no "!" and no "please"; buttons name the outcome ("Delete piece"). The
  source copy goes through the solace-wren microcopy protocol.
- **es:** as today. Venezuelan Spanish, `tú`, sentence case, no «¡», no «por favor», the
  glossary's terms; «heredar» stays banned.
- **de:** the infinitive for commands ("Schnittteil löschen"); impersonal messages; `Sie` only
  when direct address is unavoidable (the reviewer confirms); no "!", no "bitte".
- **Never translated:** overlock, flat-felled, DXF, AAMA, BOM, WebGPU, WASM, fps.
- `aria-label`s follow the same rules as visible text.

### 7.3 The lock (`src/i18n/lock.json`)

For each key and each language (`en`, `es`, `de`), the lock stores the hash of the English
source entry at the moment that translation was written or reviewed, and whether it was reviewed.
The hash is taken from the entry's source text in the TypeScript AST (a string's value, or a
function's text), so transpilation cannot change it.

- **Stale** (the English changed and the hash no longer matches): the suite fails, always. This is
  what stops German from quietly saying the old thing.
- **Untranslated** (no entry): the suite fails, always. `satisfies` only guarantees that the key
  exists; without the lock, English pasted into `de/` would pass.
- **Unreviewed:** allowed while working. The launch merge requires zero. After the launch, new
  strings enter unreviewed and reach the reviewer in batches.
- Spanish extracted verbatim from today's UI enters as reviewed: it is what María already signed.
  Spanish written fresh (where today's UI still shows English) enters unreviewed until Samuel's
  pass. English enters unreviewed until Samuel's pass; German, until the native pass.

### 7.4 Glossary test

If an English message uses a glossary term, the Spanish and German messages for the same key must
use theirs, matched by stem so that `Nahtzugaben` counts for `Nahtzugabe`. Exceptions are declared
inline with a reason. The test enforces "one term per concept", and it makes a term change
mechanical: when the reviewer changes a term, it lists every string still using the old one.

### 7.5 Review document

A private claude.ai page generated from the catalogs, which Samuel shares with the reviewer:

- Rows grouped by screen: key, English, Spanish, German, where it appears, glossary terms used,
  status.
- Screenshots of each surface in the three languages, produced by `scripts/capturas-ui.mjs`
  extended with a locale parameter, so every string is read in context.
- The reviewer marks each row as correct or proposes a correction. Claude reads the corrections,
  applies them to the catalog and updates the lock.

## 8. Verification

### 8.1 Static (pre-commit)

- `tsc -b` catches a key missing from, or extra in, `es/` and `de/`.
- A local ESLint rule, **`vina/no-literal-ui-string`**, built on the pattern of
  `vina/conversion-espacio-de-pieza` (`eslint-rules/rules/`, `eslint-rules/deuda-espacio-de-pieza.js`,
  `src/utils/geometry/__tests__/pieceSpace.trinquete.test.ts`):
  - It flags JSX text with letters; string literals in person-visible attributes (`aria-label`,
    `title`, `placeholder`, `alt`, `label` and the like); string arguments to the toast actions;
    and `t()` called at module scope.
  - It runs on UI directories only. Model-facing directories are excluded by an explicit list; an
    inline `// i18n-ignore: <reason>` covers identifiers that look like prose.
  - During the migration, `eslint-rules/i18n-debt.js` turns the rule off per file and records the
    file's count as a ceiling, a ratchet that only goes down. **The list is empty before the
    merge.**
  - After each merge of `main`, new literals from the batches fail that merge commit's own
    pre-commit and are migrated as part of the merge.

### 8.2 Unit (vitest)

- The test setup pins `en`.
- Tests that find elements by text refer to the catalog
  (`getByRole('button', { name: en.pieces.delete })`), so copy edits do not break them.
- Tests that verify signed copy (e.g.
  `src/utils/export/__tests__/bomExtractor.copyEs.loteA.test.ts`) pin `es` and keep asserting the
  literal Spanish.
- `idiomaDeOpciones.test.ts` is replaced by catalog-level checks: every tool option resolves in
  the three languages, and the lock covers the rest.
- The lock test and the glossary test (§ 7.3, § 7.4).
- `parseNumber` and `formatNumber` per locale, including the `"1.500"` case.
- Prompt assembly: for each locale, the system prompt carries the language directive and no
  hard-coded language.

### 8.3 Browser (e2e)

- `playwright.config.ts` pins `locale: 'en-US'`. The 65 specs that query Spanish text migrate
  like the unit tests, and the deploy e2e gate list in `scripts/deploy-prod.sh` must be green in
  English.
- **Language switch:** from the Vina menu to German and to Spanish; `<html lang>` follows; the
  choice survives a reload; the home's switcher sets the app's language.
- **Pseudo sweep:** under `?locale=pseudo`, a spec walks the main surfaces (empty state, Vina
  menu, dock, tool strip, a selected piece with its properties, 3D, the bottom panel tabs, the AI
  bar, a toast, a modal). It fails on any visible text, `aria-label` or `title` without the pseudo
  marks that is neither fixture data nor a declared identifier. This is the live-app census of
  what the static rule cannot see: text that comes from data, from the copilot, or composed at
  runtime.
- **German overflow at 1366×643**, the repository's reference viewport: on the same surfaces in
  `de`, no text-bearing control is clipped (`scrollWidth > clientWidth`). Each overflow is fixed
  case by case, under the UI contract.
- The two browser ratchets (`tests/e2e/superficies-por-accion.spec.ts`,
  `tests/e2e/contraste-del-cromo.spec.ts`) keep running as today.
- Home: generated pages up to date, `hreflang` reciprocal and valid, `home.spec.ts` for the three
  pages.
- In the worktree, e2e runs against its own dev server on a dedicated port. With

## 9. Process and phases

> ⚠ Not presented section by section in the conversation. Review before the plan is written.

### 9.1 Branch mechanics

- All work happens in `worktree-i18n`, with one merge to `main` at the end (D3).
- `main` is merged into the branch regularly: a plain `git merge`, never a rebase or a force-push.
  The new literals each merge brings are caught by the pre-commit (§ 8.1) and migrated in the same
  merge.
- Commits, comments, tests and specs in the branch are written in English from the first commit
  (D5).
- Dependencies are installed in the worktree with `npm ci`, not linked: a junction to `main`'s
  `node_modules` has already deleted `node_modules/.bin` twice when a worktree was removed.

### 9.3 The repository sweep (last)

Four passes, each with its own proof:

1. **Comments** are translated. Proof: file by file, the AST with comments stripped is identical
   before and after.
2. **Test titles** (`describe`, `it`, `test`) are translated. Proof: only those literals change in
   the AST, the number of tests is identical, and so is the suite's result.
3. **Identifiers and file names** are renamed with the TypeScript language service, imports
   included. Proof: `tsc -b`, the full suite, e2e and lint.
4. **Living docs** are translated and reviewed by hand: `CLAUDE.md`, `AGENTS.md`, `README.md`,
   `CONTRIBUTING.md`, `.claude/skills/contrato-de-interfaz/SKILL.md`, the glossary, and any document
   `CLAUDE.md` points to as current.

Never touched:

- the documents under `docs/reports`, `docs/plans`, `docs/superpowers`, `docs/issues` and
  `docs/business`, which `CLAUDE.md` declares a historical record;
- quotes from María and Samuel, which stay in Spanish with the English next to them;
- every identifier that is written to storage or to a file: storage keys, IndexedDB store names,
  project-format fields, zod schema keys, DXF tokens. A snapshot of this persisted surface, taken
  before the sweep, must be identical after it. Renaming one of them would break María's saved
  projects.

The sweep's commits are listed in a new `.git-blame-ignore-revs`, so `git blame` skips them.

### 9.4 Who does what

As the repository works today: implementation is delegated to Opus subagents against failing
tests written by the orchestrator; design, tests and the final "done" judgment stay with the
orchestrator; the bulk mechanical passes of § 9.3 may go to a cheaper model under the AST proofs.
Subagents neither run the four gates nor commit; the orchestrator does both.

## 10. Risks

| Risk | Mitigation |
|---|---|
| The long-lived branch drifts from `main` | Periodic plain merges; the sweep goes last; the pre-commit catches new literals at each merge |
| ~160 test files churn | Catalog references instead of literals; signed-copy tests pin `es` |

   language chosen there.
6. The repository reads in English (comments, test titles, identifiers, file names, living docs),
   except the recorded exceptions: historical documents, quotes and persisted identifiers.
