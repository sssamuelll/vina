# Colorway Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Gerber-compatible colorway system: fabricCode-based color/fabric overrides with 3D viewport integration and copilot tools.

**Architecture:** New `Colorway` entity in `projectSlice` with fabricCode-keyed overrides. Pure `resolveColorway()` function handles override resolution with fallbacks. `useColorwaySync` hook stateless-ly syncs fabric overrides to simulation. Six copilot tools for CRUD + switch + list.

**Tech Stack:** React, Redux Toolkit, Vitest

**Spec:** `docs/superpowers/specs/2026-03-25-colorway-design.md`

### Task 2: Create colorwayResolver — pure resolution function (TDD)

**Files:**
- Create: `src/utils/colorwayResolver.ts`
- Create: `src/utils/__tests__/colorwayResolver.test.ts`

- [ ] **Step 1: Write tests**

Tests should cover:
- No active colorway (null) → returns base material
- Active colorway not found → returns base material
- Piece has no fabricCode → treated as 'SELF'
- Color-only override applied
- fabricId override applied (valid ID)
- fabricId override with invalid/unknown ID → ignored, falls back to base
- textureUrl override applied
- Combined override (all three fields)
- fabricCode not in colorway overrides → base material
- `isOverridden` flag set correctly

The resolver signature:
```typescript
interface ResolvedPieceMaterial {
  color: string;
  fabricId: string;
  textureUrl?: string;
  isOverridden: boolean;
}

function resolveColorway(
  piece: { fabricCode?: string; fabricId?: string },
  colorways: Colorway[],
  activeColorwayId: string | null,
  baseFabrics: Record<string, { color: string; fabricId: string; textureUrl?: string }>,
  fabricLibraryIds: Set<string>,  // valid fabricId values for validation
): ResolvedPieceMaterial
```

- [ ] **Step 2: Run tests to verify they fail**

- [ ] **Step 3: Implement colorwayResolver.ts**

Resolution logic:
1. If `activeColorwayId` is null → return base
2. Find colorway. Not found → return base
3. `fabricCode = piece.fabricCode ?? 'SELF'`
4. Look up override in `colorway.overrides[fabricCode]`. Not found or null → return base
5. Validate `override.fabricId` if present: if not in `fabricLibraryIds`, ignore it
6. Apply valid overrides on top of base, return with `isOverridden: true`


### Task 5: Create useColorwaySync hook for simulation fabric swaps

**Files:**
- Create: `src/hooks/useColorwaySync.ts`

- [ ] **Step 1: Implement hook**

```typescript
export function useColorwaySync(): void
```

The hook:
- Reads `pieces`, `colorways`, `activeColorwayId` from project state
- Reads `pieceFabrics`, `defaultFabricId` from simulation state
- On `activeColorwayId` or `colorways` change, resolves each piece's fabricId
- Dispatches `setFabric({ pieceId, fabricId })` for pieces whose resolved fabricId differs from current `pieceFabrics[pieceId]`
- Stateless: no useRef, no snapshot. Recomputes from current state each time.

- [ ] **Step 2: Wire into app**

Call `useColorwaySync()` in a top-level component (Viewport3D or App) so it runs on every render.
